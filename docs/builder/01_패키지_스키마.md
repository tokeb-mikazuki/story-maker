# 01. 스토리 패키지 스키마 & 엔진 (v1, `ifb/1`)

> 기준 코드: `packages/engine/src/types.ts` — 이 문서와 다르면 코드가 맞다.
> 에디터·플레이어·내보내기 파일·창작마당 업로드가 전부 이 형식 하나를 쓴다.

---

## 0. 설계 원칙

1. **규칙도 데이터다.** 체력, 정신력, 생활비, 노화, 사망 판정처럼 프로토타입에서는 코드에 박혀 있던 규칙을 전부 변수·표·스크립트·트리거로 표현한다. 엔진에는 특정 게임의 규칙이 하나도 없다.
2. **수식 하나로 통일한다.** 조건, 수치, 확률, 가중치를 모두 같은 수식 언어로 쓴다. 에디터의 블록 편집기는 이 수식을 만들어 주는 UI다.
3. **결정적으로 동작한다.** 난수 상태가 세이브에 들어간다. 시드와 선택이 같으면 결과도 같으므로 세이브/이어하기, 버그 재현, 자동 시뮬레이터가 가능하다.
4. **엔진은 의존성 0, UI와 무관하다.** 에디터 미리보기, 웹 플레이어, 단독 HTML 내보내기가 같은 엔진을 쓴다.

**수용 기준 (통과)**: 손으로 짠 '도시' 프로토타입(`src/`)을 툴 패키지로 옮겨(`fixtures/city/city.ts`, 내부 테스트 전용·배포 금지) 무작위 400판을 돌렸을 때, 엔딩 분포·이벤트 도달 횟수·평균 사망 나이가 옛 엔진과 **판 단위로 정확히 일치**한다 (`packages/engine/test/city.test.ts`).

## 2. 시간과 진행

### 2.1 모드
- **story**: 날짜 없이(`calendar.unit: none`) 진행한다. `settings.start` 이벤트에서 시작해 `goto`로 이어진다. 더 일어날 일이 없는 턴이 `idleEnding.turns`번 이어지면 기본 엔딩으로 끝난다.
- **life**: 출생부터 시작하고 나이가 흐른다. 자연사 같은 종료 조건을 트리거나 엔딩 `when`으로 둔다. 조건이 하나도 없으면 검증기가 경고한다.

### 2.2 달력
`unit`: `none | day | month | year`. 시간은 정수 인덱스로 저장한다.
`start: '964.01'`, `startAge`로 시작 나이를 정하고, `format: '{y}년 {m}월'`로 표시 형식을 정한다.

### 2.3 단계(stage)와 턴
단계는 나이 범위(`ages`)나 조건(`when`)으로 정한다. 단계마다 **턴 길이**와 **턴 구성(phases)**이 다르다.

```
턴 시작 ─ turnStart 트리거
  └ phase들을 차례로:
      events  풀에서 이벤트 뽑기 (fixed | random | fixedThenRandom, 확률 chance, 개수 count)
      menu    행동 메뉴 띄우기 (actions의 pool)
      script  명령 실행
턴 끝 ─ 턴 길이만큼 시간 경과(단위마다 tick, 나이 오르면 birthday)
       → 상태이상 지속시간 감소 → turnEnd 트리거
```
`clip: true`면 턴이 다음 단계 경계를 넘지 않는다. 예: 유년기 2년 턴이 13세에서 잘린다.

### 2.4 이벤트 등장 규칙
- `pool`: 어느 풀에 속하는지. **풀이 없으면 `goto`나 시작 이벤트로만 등장한다**(분기형 소설의 기본값).
- 필터: `stages`, `ages`, `dates`, `when`, `once`, `cooldown`(턴).
- `fixed`: 조건이 맞으면 반드시 1회 발생한다(역사 이벤트, 생애 이정표). 순서는 `priority` → 시작 날짜 → 정의 순서다.
- `chokepoint`: 모든 플레이가 거쳐야 하는 지점이다. 시뮬레이터가 통과율 100%인지 검사한다.
- 랜덤: `weight`(수식 가능), 같은 `group` 연속 방지, 부정적 이벤트가 몰리면 가중치를 낮추는 톤 균형(`scheduler.toneBalance`).

## 3. 변수

```yaml
- id: 체력            # 수식에서 쓰는 이름 (한글 가능)
  type: number        # number | string | bool
  initial: 10         # 또는 initialExpr: "randint(8, 12)"  ← 난수 시작값
  min: 0
  max: 최대체력        # 수식 가능
  integer: true
  display: { as: bar, order: 1, notify: true }   # 상태창 표시, 변화 알림
- id: 최대체력
  type: number
  formula: "max(1, 10 + (용기 - 1) * 2 + 최대체력보정)"   # 파생 변수(읽기 전용)
- id: 용기
  group: 가치관       # top('가치관') → 가장 높은 변수 id
- id: 누적_플레이
  scope: meta         # 회차를 넘어 유지(해금 조건 등)
```
- **보정치**: 아이템을 소지하거나 상태가 걸려 있으면 `modifiers: { 전투: 1 }`가 읽는 값에 더해진다. 원래 값은 `base('전투')`로 읽는다.
- **태그**: 미리 선언하지 않는 자유 플래그/값이다. `has('직업', '해결사')`, `tag('명성')`. 기록용 플래그가 많을 때 쓴다.
- 기본 변수(체력·정신력)는 에디터가 새 프로젝트 템플릿으로 넣는다. 이름은 바꿀 수 있다.

## 4. 수식 언어

| 종류 | 예 |
|---|---|
| 연산 | `+ - * / %` · `== != < <= > >=`(`=`도 같음) · `and or not`(`그리고 또는 아님`, `&& \|\| !`) · `조건 ? 참 : 거짓` |
| 변수 | `체력`, `최대체력` |
| 시스템 값 | `$나이 $년 $월 $날짜 $턴 $단계 $이름 $회차 $pending $엔딩` (영문 `$age` 등도 가능) |
| 매개변수 | 스크립트 인자, `let`으로 만든 지역 변수: `$위험도` |
| 상태 함수 | `has(태그[,값])` `tag(키[,기본])` `count(접두어)` `item(id)` `status(id)` `statusLeft(id)` `seen(이벤트)` `seenAgo(이벤트)` `lookup(표, 키, 열)` `top/bottom/sum(그룹)` `base(변수)` `minOf/maxOf(변수)` `name(id)` `date('984.01')` `achieved(id)` `endingSeen(id)` |
| 난수 | `rand()` `randint(a,b)` `chance(퍼센트)` `pick(a,b,c)` |
| 순수 함수 | `min max clamp round floor ceil abs pow sqrt if num str len fmt(천단위) signed(부호)` |

## 5. 본문 템플릿

```
{$이름}{은/는} {tag('출신구', '어느 구')}에서 태어났다.          ← 값 삽입 + 조사 자동
{if 체력 < 3}숨이 가쁘다.{elif 체력 < 6}조금 지쳤다.{else}멀쩡하다.{/if}
{one}비가 온다.{or}바람이 분다.{/one}                                ← 무작위 문장
```
조사 `{이/가} {을/를} {은/는} {와/과} {으로/로} {아/야} …`는 바로 앞 글자의 받침을 보고 고른다. 숫자와 따옴표·괄호 뒤에서도 동작하고, `ㄹ`받침 뒤에서는 `로`를 쓴다.

## 6. 선택지와 결과

```yaml
choices:
  - text: 문을 부순다
    requires: "전투 >= 3 or item('쇠지렛대') > 0"   # 미충족 시 회색 + "필요: 전투 3 이상 또는 쇠지렛대" 자동 생성
    hidden: false                                  # true면 미충족 시 아예 숨김
    check: { skill: 전투, difficulty: 2 }          # 판정 → success / failure, 확률을 '유리/불리'로 표시
    success: { text: …, do: [ … ], goto: 다음이벤트 }
    failure: { … }
  - text: 뛰어내린다
    results:                                       # 가중치 랜덤 결과 (확률 사망 등)
      - { weight: 7, text: 무사히 착지했다. }
      - { weight: "3 + 부상", text: 다리가 부러졌다., do: [{ do: end, ending: 추락사 }] }
```
판정 공식은 `settings.check.formula`로 바꿀 수 있다. 기본값은 `50 + 15 × ($skill − $difficulty) + $bonus`이고 5~95%로 제한한다. 확률 표시는 이름/퍼센트/둘 다/숨김 중에서 고른다.

## 7. 명령 (RPG Maker의 이벤트 명령에 해당)

| 명령 | 설명 |
|---|---|
| `set` / `add` | 변수 대입 / 증감(범위 자동 제한) |
| `let` | 지역 변수 `$이름` |
| `tag` / `untag` | 태그 설정·누적(`add`) / 제거(키, 값 일치, 접두어) |
| `item` / `status` | 아이템 증감, 상태 부여·해제(지속 턴, 중첩). `silent`로 알림 끄기 |
| `text` / `note` / `image` | 결과 본문 / 작은 알림 / 일러스트 |
| `if` / `random` / `check` | 조건 분기 / 가중치 분기 / 판정 분기 |
| `goto` | 다음에 이 이벤트로 |
| `call` | 공용 스크립트 호출(매개변수) |
| `end` | 엔딩 |
| `advance` / `endTurn` | 시간 경과 / 남은 단계를 건너뛰고 턴을 n번 마침("평온하게 1년 보내기") |
| `record` | 인생표에 기록 |
| `achieve` | 도전과제 달성 |

## 8. 트리거 (자동 규칙)

| `on` | 언제 | 예 |
|---|---|---|
| `watch` | 매 선택 직후·장면 전환마다 조건 감시 | 체력 ≤ 0 → 부활 아이템 소모 또는 사망 / 정신 붕괴 → 위기 이벤트 / 경험치 → 등급 상승 |
| `tick` | 시간 최소 단위마다 | 월말 정산, 자연 회복 |
| `birthday` | 나이가 오를 때 | 노화, 확률적 자연사 |
| `turnStart` / `turnEnd` | 턴 경계 | '이번 달' 태그 정리 |
| `stageEnter` | 단계 진입 | 성인식 |
| `start` / `end` | 새 게임 / 엔딩 직전 | 회차 카운트 |

`watch`는 한 번 정리할 때 트리거마다 최대 1회만 실행해서 무한 반복을 막는다. 한 번만 실행할 트리거는 `once`로 지정한다.

## 9. 엔딩 · 결산 · 인생표 · 도전과제

- **종료 조건**: 엔딩의 `when`(예: `체력 <= 0`), `end` 명령(금지 선택지, 확률 사망), `idleEnding`(이야기 소진), `maxTurns`(안전장치). 여러 조건이 동시에 참이면 `priority`가 높은 것을 쓴다.
- **결산(epilogue)**: header → 엔딩 본문 → 조건부 문단(`order` 순, 문단 안에서도 줄마다 조건) → footer. 엔딩을 따로 만들지 않아도 지금까지의 결과를 모은 기본 결산이 나온다.
- **인생표**: 이벤트의 `record`, `record` 명령으로 쌓인 `{날짜, 나이, 문구, 중요도}`. 엔딩 화면에서 타임라인으로 보여주고 이미지로 저장한다(UI 단계에서 구현).
- **도전과제**: `when` 조건이나 `achieve` 명령으로 달성한다. 메타(회차 간)에 저장하고, 출신 해금(`unlock: "achieved('…')"`) 등에 쓸 수 있다.

## 10. 실행 API (UI가 쓰는 것)

```ts
const run = new Runner(pkg, { seed, meta: localStorageMetaStore });
run.scene        // name | origin | event | menu | result | end
run.choose(i); run.proceed(); run.setName('…'); run.useItem('id');
run.hud()        // 상태창: 표시 변수, 아이템(사용 가능 여부), 상태
run.save()       // JSON 세이브 → new Runner(pkg, { save })로 이어하기
run.jumpTo(id)   // 테스트 플레이: 아무 이벤트로 이동
```

## 11. 제작 도구용 기능

- **`validatePackage(pkg)`**: 수식·본문 문법, 없는 참조(변수, 이벤트, 아이템, 상태, 표/열, 스크립트, 엔딩, 에셋), 파생 변수에 대입, 아무 단계도 뽑지 않는 풀, 도달 불가 이벤트를 찾는다. 각 문제에 `path`가 붙어 있어 에디터에서 해당 위치로 바로 이동한다.
- **`simulate(pkg, { runs })`**: 무작위로 n판을 플레이해 엔딩 분포, 이벤트 도달 횟수, 한 번도 안 나온 이벤트, 초크포인트 통과율, 턴 수·나이 통계, 막힌 판, 오류(시드 포함, 재현 가능)를 보고한다.
